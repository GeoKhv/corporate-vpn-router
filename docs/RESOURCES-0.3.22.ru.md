# Рабочие ресурсы в 0.3.22

В меню Router откройте «Рабочие сайты…». В таблице видны имя, охват, порты и алиас. Введите имя и нажмите «Добавить». Чтобы изменить существующее правило, выберите его, нажмите «Изменить», отредактируйте поля и подтвердите изменение кнопкой в строке ввода. «Отменить правку» сначала сбрасывает ввод, затем позволяет вернуть прошлое состояние списка.

Вставьте одну или несколько ссылок, по одной на строку, и нажмите «Разобрать адреса…». Предпросмотр показывает предполагаемый порт и уже действующее разрешение. У маски *.lab.example область включает lab.example и его поддомены. Более точное правило определяет порты своего имени. Отметьте нужные строки и добавьте их в черновик. Пути, параметры и фрагменты в профиль не входят. Поменять порты существующего имени можно вручную. Кнопка «Проверить подключение» проверяет один адрес по действующей политике.

Для короткого имени сначала используется сохранённый алиас. Поисковые суффиксы берутся из текущего сеанса и поля «Свои суффиксы». Введите дополнительные полные домены через запятую. Поиск доступен при работающем корпоративном DNS и только в разрешённых областях. Для нового домена введите полное имя и утвердите правило. При нескольких совпадениях выберите имя в предпросмотре. Алиас становится доступен системному DNS при подключении с обновлёнными правилами. Сертификат HTTPS должен подходить к имени, указанному приложением.

«Применить правила» проверяет весь черновик. При активном туннеле Router сохраняет его до следующего подключения. Чтобы применить сейчас, отключитесь и подключитесь снова. Новые разрешения помощника подтверждаются штатным запросом macOS. После отмены черновик доступен для исправления или повторной попытки. Экспорт содержит рабочие правила, порты, алиасы и ручные суффиксы. Импорт этого файла заменяет правила в черновике и сохраняет местные исключения для входа.

**Проверка на основном Mac.** На изолированном профиле через окна AppKit проверены добавление двух правил, покрытый поддомен, явное переименование и отмена, пакетная вставка, сохранение любого TCP и алиаса, закрытие редактора с незавершённым полем, отмена утверждения и успешный повтор с тестовым помощником. Команда меню вернула закрытое и свёрнутое главное окно. На рабочей установке проверены перенос профиля 0.3.20, подтверждение политики настоящим помощником, вход ключом доступа и HTTPS с проверкой сертификата. При потере транспорта в 0.3.22 рабочие IPv4/IPv6 оставались на utun73 во всех десяти замерах. Рабочий DNS отказал в разрешении, TCP по сохранённому адресу был заблокирован, внешний HTTPS через личный VPN вернул 200.

Проверены пакетные TCP 22 и 6443 на контролируемых сервисах, NXDOMAIN, недоступность DNS и выбор из нескольких совпадений. Доступность SSH, Kubernetes и веб-стенда зависит от сети и учётной записи. На втором Mac эту версию пока не проверяли.

**Коллеге.** После обновления подключитесь из меню Router и откройте привычный рабочий ресурс по короткому имени в своём приложении.

**Откат.** Завершите рабочий сеанс. Sparkle сохраняет предыдущий пакет в ~/Library/Application Support/Corporate VPN Router/UpdateBackups. Верните его на место текущего приложения. Если меняли правила, восстановите совместимую копию work-sites.json и подтвердите прежний список штатным действием настройки помощника. Сохраните таблицу Selective/domain-map.json. В редакторе предыдущий список можно загрузить в черновик кнопкой «Предыдущие правила».
