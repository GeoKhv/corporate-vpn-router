# Local colleague build · 12 November 2026

Current local candidate: **demo.2-private / build 10**. It fixes a reported first-launch
failure when the user put the app in `/Applications`: demo.1 mistook that same app
for a conflicting installation. Both `/Applications` and `~/Applications` are now
recognized. The tests below describing native quarantine are historical demo.1
observations; the new demo.2 signature has not had its Gatekeeper approval chain
remeasured. Do not reuse that count as a new native acceptance result.


The preferred distribution is a ZIP containing one ready `Corporate VPN Router.app`.
There is no distribution installer app. The private colleague ZIP and its work-site
profile must never be uploaded to the public repository or releases. Both output
folders, `dist/` and `.private/`, are ignored by Git. Nothing was published.

Build locally on Apple Silicon, without Actions or additional downloads:

```sh
bash scripts/package-demo.sh /path/to/published-beta.6-macOS-arm64.zip /path/to/private.cvrprofile
python3 scripts/test-demo.py /path/to/private-demo.zip /path/to/published-beta.6-macOS-arm64.zip
```

The builder pins the original ZIP and ad hoc application identity, rebuilds the
menu with `CVR_DEMO_SINGLE`, sets bundle build 10 / revision `demo.2-private`, and
validates a strict work-sites schema. Only sites, exact pre-login exceptions and
ports are accepted; no credential, trust receipt, pin, cookie or token fields are
accepted. Every existing engine, native SOCKS worker and runtime resource is
verified byte-for-byte against the original beta.6.

For a fresh install, extract the ZIP, move the app into `~/Applications` or `/Applications`, and open
it. First launch creates a missing menu login plist and a missing work-sites file;
it never overwrites an existing plist or work-sites file. Login starts disconnected
and without windows. Existing profile, DNS, routes, trust and other VPNs are not
changed by installation. Chrome routing setup is an explicit action from the main
window, separate from installation and authentication. It still needs the owned
Chrome profile and its one-time browser restart/check.

For an update, finish the existing Router first and open the new app from its
separate extraction directory. The installer-fix.1 transaction validates code and
ownership, keeps the menu lock, refuses a running installation, saves an exact
rollback app and restores it on transaction failure. This single-app variant
continues the first menu run in the same process; engine commands use the installed
resource path. It does not launch a second shell or second menu process. The normal
build and the existing published installer-fix.1 distribution remain available.
Do not overwrite a running app with Finder. To roll back, finish Router, preserve
the new bundle elsewhere and restore the transaction's original backup to the
canonical app path. Keep private settings and the beta.6 Chrome profile.

The main window keeps state, authorization method and next action. Opening it or
pressing Connect before routing enrollment no longer opens the site editor.
Work sites and diagnostics remain explicit actions. The primary Chrome setup
button avoids requiring the user to discover it inside the editor.
