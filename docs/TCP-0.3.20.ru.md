# Рабочие TCP-ресурсы · кандидат 0.3.20

Для уже настроенных Mac с Apple Silicon и macOS 26+. Статус этой сборки — локальная приёмка. Публичный канал обновлений пока предлагает 0.3.19. На первом Mac проверены перенос прежних разрешений, новый вход с ключом доступа и соединение с рабочим HTTPS-сервисом обычным клиентом по IPv4 и IPv6. Одновременно SOTA была подключена и внешний сайт вернул HTTP 200.

В разделе «Рабочие сайты» выберите полное имя узла или домен вместе с поддоменами. Введите TCP-порты через запятую. Звёздочка разрешает любой TCP-порт внутри указанной области. Самое точное совпавшее правило определяет порты. Например, домен лаборатории может разрешать 443, а отдельный сервер внутри него — 22 и 6443. Импорт существующего профиля сохраняет заданные в нём порты.

Для отдельного сервера можно привязать короткое имя, совпадающее с первой частью полного имени. Сборка проверяет имя через DNS внутри туннеля, затем выделяет адрес из существующей таблицы. Выдача того же синтетического адреса для полного и короткого имени проверена на локальном DNS-сервисе. Системная обработка короткого имени при наличии других поисковых суффиксов требует проверки на macOS.

Кнопка «Проверить подключение» принимает имя, адрес с портом или URL. Для неизвестного полного имени можно добавить точное правило. Перед добавлением проверьте принадлежность ресурса организации. Редактор показывает охват и изменяемые порты. Сохранение выполняется при остановленном туннеле. Для изменения разрешений помощника macOS запрашивает подтверждение. Вернуться к предыдущему списку можно через «Вернуть прежние правила» и сохранение.

Для разрешённого назначения анализатор сверяет профиль с ответом помощника, проверяет рабочий DNS, владельца синтетического адреса и маршрут. Затем создаёт одно TCP-соединение через проверенного владельца корпоративного SOCKS. Для HTTPS системный curl проверяет сертификат и запрашивает только заголовки по уже открытому корпоративному TCP-соединению. Отчёт показывает HTTP-код, включая запрос входа или отказ в доступе. Вход в SSH, Kubernetes или веб-приложение подтверждает соответствующий клиент. Прямые IP, CIDR и передача UDP этой возможностью не поддерживаются.

После системной приёмки для проверки у коллеги потребуется два действия в привычных приложениях:

1. Открыть сохранённое подключение Termius по короткому имени на порту 22. Появление обычного приглашения SSH подтверждает доступность сервиса.
2. Открыть сохранённый кластер Lens по полному имени на порту 6443. Отдельно отметить доступность API и результат входа под своей учётной записью.

Для отката сначала завершите рабочий сеанс. Перед обновлением сохраните предыдущую версию приложения и копию work-sites.json. При возврате на 0.3.19 восстановите профиль прежнего формата, приложение из резервной копии и поставляемый с ним помощник через штатное действие настройки. Таблица domain-map.json остаётся на месте. Системный откат на первом Mac ещё не проверен.
