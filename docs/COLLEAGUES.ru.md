# Постоянный локальный прокси для Chrome · Mac Beta 0.2.0-beta.6

Исправленный установщик: **[DMG beta.6 · installer-fix.1](https://github.com/GeoKhv/corporate-vpn-router/releases/download/v0.2.0-beta.6/Corporate-VPN-Router-0.2.0-beta.6-macOS-arm64-installer-fix.1.dmg)** и **[SHA-256](https://github.com/GeoKhv/corporate-vpn-router/releases/download/v0.2.0-beta.6/Corporate-VPN-Router-0.2.0-beta.6-macOS-arm64-installer-fix.1.dmg.sha256)**. Прежние DMG и ZIP сохранены в релизе; для новой установки используйте файл с суффиксом **installer-fix.1**.

1. Скачайте оба файла в одну папку. В Терминале из этой папки выполните `shasum -a 256 -c Corporate-VPN-Router-0.2.0-beta.6-macOS-arm64-installer-fix.1.dmg.sha256`.
2. Откройте DMG и дважды нажмите **Установить Corporate VPN Router**. Перетаскивать приложение не нужно. Оно устанавливается в **~/Applications**, без администратора. После запуска Router извлеките DMG.
3. Если macOS заблокировала **Установить Corporate VPN Router**, откройте **Системные настройки → Конфиденциальность и безопасность → Всё равно открыть** и подтвердите **Открыть** для этого установщика. Если отдельное предупреждение затем относится к **Corporate VPN Router**, разрешите тем же способом именно его и откройте из **~/Applications**. При обновлении macOS может запросить разрешение для заменённого файла снова. Второй раз запускать установку не нужно. Не отключайте Gatekeeper и не снимайте карантин командами.

Перед обновлением завершите Router через его меню после окончания рабочего сеанса. Пока Router запущен, установщик откажет с сообщением «VPN-сеанс сохранён»; он не завершает VPN, Chrome или Sota. Существующая beta.6 обновляется на месте. Прежнее приложение сохраняется в `~/Library/Application Support/Corporate VPN Router/rollback-….app`. Сайты, учётные записи, настройки, профиль Chrome, HTTP-служба и существующий файл автозапуска сохраняются. В том числе сохраняется отключённый автозапуск. Для новой установки создаётся пользовательский LaunchAgent, запускающий приложение с `--login` при следующем входе в macOS. Повторно настраивать Chrome для той же beta.6 не нужно.

При ошибке установщик показывает операцию, путь и системную причину. Ошибка записи автозапуска после замены приложения отменяет замену и возвращает прежнюю копию. Если macOS запретила только запуск уже установленной копии, сообщение прямо говорит «Приложение установлено». Сохраните полный текст сообщения для диагностики; не удаляйте папку настроек. Копию в общей `/Applications` установщик не заменяет: после завершения Router сохраните её в резервной папке и повторите установку в `~/Applications`.

Установщик и приложение подписаны **ad hoc**, без Developer ID и нотариализации; DMG не подписан. Политика организации может запрещать индивидуальное разрешение запуска — тогда установка этим способом не поддерживается. Требования: **Apple Silicon, macOS 13+**, совместимый настроенный Check Point и приватный список рабочих сайтов. Корпоративные данные в DMG не входят. Движок VPN и встроенный runtime совпадают с опубликованной beta.6; исправлены установка и определение пути запуска. Идентификатор исправления находится в `Contents/Resources/INSTALLER_REVISION`.

**Откат переустановки beta.6:** завершите Router, переместите текущую копию из ~/Applications в резервную папку, скопируйте выбранную `rollback-….app` обратно в ~/Applications с именем **Corporate VPN Router.app** и откройте её. Сначала проверьте версию в `Contents/Resources/VERSION`: этот способ относится к сохранённой beta.6. Путь автозапуска и данные остаются прежними. Для возврата к beta.5 используйте отдельную процедуру ниже. Подробности сборки и проверки — [DMG.md](DMG.md).

1. Откройте в меню Router **Рабочие сайты…**. При обновлении используется существующий список. Для первого запуска импортируйте приватный профиль коллег, проверьте порты и точные имена шлюза и авторизации. Сохраните список. Эти данные не входят в дистрибутив.
2. Сохраните незавершённые формы и загрузки. Выберите **Настроить Chrome…**. Router запустит фоновую службу и откроет в macOS свой профиль с единственной настройкой: Chrome использует локальный HTTP/CONNECT-прокси. В «Основные → Управление устройством» подтвердите загруженный профиль Router. При переходе с beta.5 macOS заменяет наш прежний профиль под тем же идентификатором. Если в настройках видна только строка прежнего профиля под «Пользователь», запрос больше не ожидает установки. Повторите **Настроить Chrome…** в Router: под **Загружено** появится **Corporate VPN Router · beta.6 · Локальный прокси Chrome**. Дважды нажмите эту строку и подтвердите установку. Чужой профиль не удаляется. Wi-Fi, Ethernet, Sota и системный DNS не перенастраиваются.
3. Приложение один раз штатно перезапускает Chrome и открывает страницу проверки. Дождитесь подтверждения запроса **из браузера**. Если проверка не прошла, не начинайте рабочий сеанс. Ручное обновление политики и расширение не требуются.
4. В главном окне выберите **Ключ доступа в браузере** либо **Код + пароль**, нажмите **Подключить**. Для изменения доменов откройте **Рабочие сайты…** → добавьте точное имя либо имя с поддоменами → **В список** → **Сохранить список**. Существующие потоки закрываются, в том числе активные загрузки; повторите прерванный запрос. Для этой операции не требуется подтверждать профиль или перезапускать Chrome.
5. **Отключить рабочий туннель** завершает рабочую сессию. Личные HTTP(S)-страницы продолжает обслуживать независимый маршрутизатор. При падении самого маршрутизатора в Chrome временно недоступны оба маршрута до его перезапуска через launchd. Для рабочих адресов нет запасного прямого соединения.

**Откат:** завершите корпоративный сеанс и выберите **Вернуться к beta.5…**. В «Управление устройством» дважды нажмите **Corporate VPN Router · Chrome** в разделе **Загружено** и подтвердите установку. Строка **Corporate VPN Router · beta.6 · Локальный прокси Chrome** в разделе **Пользователь** показывает, что пока действует beta.6. После установки исходного профиля снова выберите откат в Router. Router сверяет профиль с резервной копией, возвращает исходный список и открывает проверенную копию beta.5. Изменения списка, сделанные после миграции, не становятся частью старого профиля автоматически. Для повторного рабочего подключения потребуется MFA.

**Границы:** режим предназначен для обычного Chrome и HTTP(S) по доменным именам. HTTPS остаётся зашифрованным до сайта; Router не устанавливает CA. Исключения для входа действуют только для точных имён. Loopback, в том числе возврат Passkey на 7779, обрабатывается самим Chrome. Прямой IP не идентифицирует рабочий домен; этот режим не гарантирует маршрутизацию UDP/WebRTC, иных браузеров и программ. Для незашифрованного HTTP поддерживается тело известной длины. Защищённые WebSocket и файлы HTTPS передаются внутри CONNECT.
