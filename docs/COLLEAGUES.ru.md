# Установка и работа · 0.3.20

## Если Router уже настроен

1. Нажмите **«Проверить обновления»** в приложении.
2. Для 0.3.20 выберите **«Загрузить и установить»**. Приложение сохранит резервную копию и завершит свой рабочий сеанс перед заменой.
3. После перезапуска подключитесь заново. MFA требуется снова; пароли и одноразовые коды не воспроизводятся.

При переходе со старого помощника подтвердите в macOS перенос разрешений. Затем можно открыть «Рабочие сайты…» из строки меню и импортировать согласованное правило. Перед сохранением проверьте имя и порты. [Рабочие TCP-ресурсы](TCP-0.3.20.ru.md).

Для ручного обновления: скачайте [ZIP и контрольную сумму](https://github.com/GeoKhv/corporate-vpn-router/releases/tag/v0.3.20), завершите Router через Cmd+Q и замените его `.app` в прежней папке. Не запускайте резервную копию как второе приложение и не удаляйте Application Support.

## Первый запуск

Текущий пакет рассчитан на Apple Silicon и macOS 26+. На новом Mac нужен согласованный STARTER с рабочим профилем; общий ZIP обновления сам по себе не содержит полного набора настроек новой установки. Порядок передачи STARTER описан в [AGENTS.md](../AGENTS.md).

Официальный Check Point должен быть установлен и настроен по инструкции организации. Router читает проверенную конфигурацию и не считает все сайты взаимозаменяемыми. Для поддержанного альтернативного сайта выбор автоматизирован; если идентичность шлюза ещё не подтверждена, приложение должно объяснить необходимое действие, а не ослаблять проверку сертификата. Не удаляйте остальные сайты Check Point ради выбора одного.

Если macOS блокирует первый запуск из-за отсутствия Developer ID/notarization, используйте штатное «Всё равно открыть» для полученного от доверенного источника приложения. Не отключайте Gatekeeper и не удаляйте карантин командами.

## Вход

Выберите «Код + пароль» и введите рабочий логин. Следуйте подписи каждого поля: OTP — одноразовый код, пароль — постоянный пароль. Техническое слово `password` в протоколе может обозначать любой секретный фактор; начиная с 0.3.19 Router подставляет подпись из настроек выбранного шлюза. Конкретные динамические запросы шлюза сохраняются.

Предварительно входить в штатном Check Point для уже поддержанного сайта не требуется. Если официальный VPN уже подключён, Router запрашивает согласие на переключение. При отказе этот сеанс сохраняется. Для IPsec доступен только вход кодом и паролем; браузерный вход остаётся для совместимых SSL-профилей.

## Диагностика и передача отчёта

Откройте «Диагностика…». Статусы шлюза, авторизации, туннеля, SOCKS и DNS относятся к разным этапам. «HTTPS одного сайта» показывает выбранный адрес и результат отдельного ограниченного GET-запроса. Красная строка для одного адреса может сочетаться с работающими другими сайтами; она не доказывает отказ всего VPN.

Нажмите «Сохранить и открыть логи…» и выберите папку. После успешной записи отчёт откроется, а **сам файл попадёт в буфер** — его можно вставить через Cmd+V в приложение, поддерживающее вставку файлов. При отмене или ошибке сохранения буфер не меняется. В отчёт попадают отфильтрованные диагностические поля, включая коды curl/HTTP/TLS; пароли и OTP присылать не нужно.

Если интернет работает без внешнего VPN, но пропадает вместе с ним, сначала сохраните диагностику и различите DNS, маршруты и работающие процессы. Не сбрасывайте все маршруты и не завершайте процессы только по похожему имени. [Разбор нескольких сайтов и восстановления](MULTISITE-RECOVERY.ru.md).

## Ограничения и откат

На компьютере получателя подтверждён рабочий сеанс 0.3.18 с доступом к рабочим и внешним сайтам. Длительная работа, сон/пробуждение и повторный вход 0.3.19 на нём пока не подтверждены. [Подробности проверки](VALIDATION.md).

Для отката используйте точную резервную `.app` после завершения текущего сеанса. Не заменяйте личные данные, Keychain или настройки внешнего VPN. [Порядок отката](UPDATES.ru.md#откат). [Историческая инструкция beta.6](archive/COLLEAGUES-beta6.ru.md).
