# Установка и проверка для коллег

## До установки

Согласуйте использование с ИТ-службой. Нужны Mac Apple Silicon, разрешённый корпоративный клиент Check Point, собственная учётная запись и точный список корпоративных доменов, DNS и портов. Запросите все рабочие и SSO-хосты. Публичные хосты входа Check Point не следует добавлять в корпоративный список: они должны работать до поднятия туннеля.

Beta не знает конфигурацию вашей организации и не извлекает её из чужих логов. Она не содержит готовых корпоративных правил, CA, учётных записей или лицензий VPN-клиента.

## Установка

Скачайте архив из GitHub Release и проверьте SHA-256 командой `shasum -a 256 ИМЯ.zip`. Сверьте результат с опубликованным `SHA256SUMS.txt`. Это проверяет целостность загрузки; файл хеша из того же Release не является независимой подписью поставщика.

Распакуйте ZIP. Откройте `Install.command` или приложение. Программа устанавливается в `~/Applications/Corporate VPN Router.app`, настройки — в `~/Library/Application Support/Corporate VPN Router/`. Администратор для самого локального сервиса не нужен. Для установки/разрешений Check Point и управляемых CA ИТ-служба может требовать администратора или MDM.

У Beta нет Developer ID и нотариализации. После попытки открытия macOS может предложить **System Settings → Privacy & Security → Open Anyway**. Используйте этот порядок только если проверили происхождение файла и политика организации разрешает запуск. Не отключайте Gatekeeper. [Официальная инструкция Apple](https://support.apple.com/en-us/102445).

Введите доменные суффиксы без `https://`, путей и `*.`; суффикс включает все поддомены. Введите корпоративные IPv4 DNS через запятую. По умолчанию разрешён только TCP 443, SOCKS-порт — 1089. Нажмите **Save & Start**, затем войдите в штатный Check Point. Приложение не хранит пароль и не автоматизирует MFA.

Откройте **Certificates & Permissions…**, введите реальные хосты HTTPS и запустите проверку. Если CA отсутствует, получите файл и независимый SHA-256 от ИТ-службы. Продолжайте по [мастеру сертификатов](CERTIFICATES.ru.md). Уже работающие сертификаты менять не требуется.

## Как читать состояние

| Состояние | Значение и действие |
|---|---|
| UNCONFIGURED | Сначала задайте корпоративную конфигурацию |
| STOPPED | Нажмите Save & Start; прокси не работает |
| WAITING_FOR_VPN | Корпоративный туннель не подтверждён; запросы блокируются. Проверьте вход Check Point, DNS и маршруты |
| TUNNEL_READY | Туннель обнаружен; успешный DNS/HTTPS ещё не доказан |
| READY | Последнее переданное соединение установлено; это не подтверждение пользовательского входа в сервис |
| CONNECTION_BLOCKED | Последняя попытка отклонена из-за DNS, маршрута или соединения; откройте диагностику |
| RECOVERING | Нет свежего статуса сервиса; не считайте туннель готовым |
| PROXY_FAILED | Локальный порт занят или недоступен; выберите свободный порт и повторите запуск |

## Подключение клиента

Клиент должен поддерживать SOCKS5 с передачей имени прокси, без локального DNS для рабочих запросов. В `curl` используйте `--socks5-hostname` либо схему `socks5h://`. Отключите собственные bypass-исключения и DIRECT fallback. Для HTTPS сохраняйте проверку сертификатов.

Приложение принимает только настроенные корпоративные назначения. Внешние сайты через этот порт намеренно отклоняются. Они могут работать в обычном клиенте через ваш внешний VPN; продукт не управляет его подключением.

Кнопка **Export PAC…** создаёт частный файл: корпоративные суффиксы получают только `SOCKS5`, остальные — `DIRECT`. Импортировать его нужно самостоятельно в клиент с принудительным применением PAC и удалённым SOCKS DNS. Клиенты могут обходить неработающий или отключённый PAC. Beta не меняет и не сертифицирует ваш браузер или расширение. Если нельзя обеспечить отсутствие fallback, гарантия блокировки ограничена самим SOCKS-сервисом.

## Проверка перед работой

В Terminal задайте путь к бинарнику:

```sh
CVR="$HOME/Applications/Corporate VPN Router.app/Contents/MacOS/CorporateVPNRouter"
"$CVR" --status
"$CVR" --diagnose mail.corp.example.com
"$CVR" --certificates mail.corp.example.com wiki.corp.example.com
"$CVR" --permissions
```

Подставляйте только свои разрешённые хосты. `--diagnose` проверяет DNS, маршрут и TCP, но не TLS. `--certificates` выполняет обязательную проверку TLS и HTTPS HEAD без паролей/cookies; его вывод содержит корпоративные данные и предназначен только для локального просмотра. HTTP 401/302 после успешного TLS часто означает штатное требование входа или перенаправление, а не неисправный VPN.

Затем выполните команду `curl` из README. Остановите только Router кнопкой **Stop** и повторите запрос: ожидается отказ соединения с прокси. Если страница продолжает открываться, клиент обходит настройки — сначала устраните обход. Нажмите **Save & Start** для возврата.

Если диалог ключа доступа завис, сначала отмените конкретную попытку и начните свежий штатный вход в Check Point. Не запускайте одновременно несколько попыток авторизации. Подтверждение Touch ID, пароля Mac или другого ключа выполняет сам пользователь. Зависание такого диалога само по себе не означает ошибку CA и не является основанием для изменения доверия.

В согласованное время проверьте отключение Check Point, восстановление, смену сети, сон и перезагрузку. При отсутствии VPN рабочие запросы должны отклоняться. После возврата туннеля приложение перепроверяет состояние. После перезагрузки сервис запускается после входа пользователя; MFA может потребовать ручного входа. Эти сценарии нельзя считать выполненными по одному наличию LaunchAgent.

При смене сети может потребоваться отдельная авторизация Wi-Fi. Сначала восстановите сам доступ к сети, затем Check Point. Время этого этапа не является временем восстановления Router. Если рядом работает старый экспериментальный прокси, его состояние проверяется отдельно от порта новой Beta.

## Остановка, обновление и полный откат

**Stop** выгружает сервис и убирает его автозапуск до следующего **Save & Start**. Закрытие окна приложения сервис не останавливает. Новая установка сохраняет предыдущую версию приложения, изменение настроек — предыдущую конфигурацию.

```sh
"$CVR" --stop
"$CVR" --restore-config
"$CVR" --rollback
```

`--restore-config` возвращает предыдущие настройки; `--rollback` — предыдущую версию приложения, если она была. Они не откатывают чужие VPN и вручную установленные CA.

Для полного удаления сначала откройте **Certificates & Permissions… → Undo an import…**, если сами импортировали CA через мастер. Подтвердите удаление каждого точного отпечатка. Это может повлиять на другие приложения вашего пользователя. Не удаляйте уже существовавшие или управляемые ИТ-службой сертификаты.

Затем выполните `Uninstall.command` из архива либо `"$CVR" --uninstall`. Частные настройки и квитанции сохранятся. Для их удаления есть `--uninstall --purge`; он запрещён, пока остаются неотменённые квитанции импорта CA. Если приложение уже удалено, команды доступны из бинарника в скачанном архиве.

Уберите прокси/PAC из клиента самостоятельно. Приложение не меняет системные proxy/DNS/маршруты, поэтому возвращать их не требуется. Отдельно установленный старый Router, внешний VPN, Check Point и его индивидуальная авторизация сохраняются.
