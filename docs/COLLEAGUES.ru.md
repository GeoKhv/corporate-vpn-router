# Системный режим на Mac

Эта инструкция относится к локальному кандидату 0.2.0-beta.6 для Apple Silicon. На основном Mac с активной Sota проверка выявила несовместимость. Системные параметры основной службы не указывают на Router. На этом Mac сохранена beta.5. Для установленной beta.5 используйте [инструкцию её выпуска](https://github.com/GeoKhv/corporate-vpn-router/blob/v0.2.0-beta.5/docs/COLLEAGUES.ru.md).

### Включение

1. Убедитесь, что официальный клиент Check Point настроен и приватный профиль коллег получен по внутреннему каналу. Откройте значок VPN → **Рабочие сайты**. При обновлении приложение читает существующий список. При первой настройке импортируйте приватный профиль, проверьте рабочие домены, точные имена шлюза и провайдера входа, нажмите **Сохранить список**.
2. Если ранее использовалось прокси-расширение, выключите его штатным переключателем в списке расширений Chrome. Установку и сохранённую конфигурацию расширения можно оставить. Во время миграции с beta.5 её действующая политика продолжает защищать Chrome до переключения.
3. Сохраните незавершённые формы и загрузки в Chrome. Нажмите **Включить системный прокси…**. При первом переходе приложение штатно перезапускает Chrome, чтобы прежние соединения закрылись. macOS может запросить подтверждение администратора. Приложение сохраняет настройки служб Wi‑Fi и Ethernet по их идентификаторам и проверяет эффективные настройки основной сети. Для HTTP и HTTPS используется один локальный адрес. Если основной VPN публикует собственные параметры и браузер не увидит системный прокси, переход должен завершиться до снятия профиля beta.5. При сообщении о несовместимости сохраните рабочий режим и обратитесь к сопровождающему.
4. Выберите **Ключ доступа в браузере** или **Код + пароль**, затем **Подключить**. Проверьте рабочий и личный сайты в обычном Chrome. Редактор списка применяет новые правила кнопкой **Сохранить список**. Существующие соединения могут прерваться, в том числе текущая загрузка файла.
5. **Отключить рабочий туннель** завершает корпоративный сеанс. Фоновый маршрутизатор продолжает обслуживать личные запросы. Для следующего рабочего сеанса потребуется вход. После закрытия меню системные параметры продолжают указывать на фоновую службу.

### Возврат

**Вернуть прежние сетевые настройки…** восстанавливает параметры каждой службы для HTTP и HTTPS. Если после включения режима другая программа изменила адрес, порт или состояние протокола, приложение оставляет эту группу параметров текущему владельцу. После явного возврата системного прокси защита рабочих запросов этим режимом прекращается.

Для полного возврата версии завершите рабочий туннель и выберите в меню **Вернуться к beta.5…**. Для режима beta.5 требуется исходный пользовательский профиль Chrome. Приложение предложит открыть сохранённый профиль для штатного подтверждения macOS и продолжит откат при повторном выборе команды. Если проверенной копии приложения нет, дистрибутив и инструкция доступны на [странице beta.5](https://github.com/GeoKhv/corporate-vpn-router/releases/tag/v0.2.0-beta.5).

### Область действия

Системный прокси влияет и на другие программы, которые его учитывают. Ожидаемая область приёмки — HTTP и HTTPS по доменному имени в обычном Chrome. HTTPS идёт через CONNECT с обычной проверкой сертификата браузером. Рабочий маршрут принимает только разрешённые домены и порты, передавая имя в SOCKS5 для DNS внутри туннеля. Исключения для авторизации совпадают только с полным именем. Обычные соединения используют маршрут macOS, включая Sota, если она активна.

Прямой IP не идентифицирует рабочий домен. Отдельно учитываются приложения и протоколы, игнорирующие HTTP-прокси, локальные адреса, WebRTC, сторонние контроллеры и смена основной сетевой службы. Если новая сеть не публикует настройки Router, проверку режима нужно повторить до открытия рабочих страниц. В кандидатной сборке для обычного HTTP поддерживается тело известной длины, для HTTPS и защищённых WebSocket данные передаются внутри CONNECT. Корпоративные сертификаты, логины и списки доменов в архив не входят.
