# Несколько сайтов Check Point и восстановление сети

## Текущая версия 0.3.19

Для поддержанного сайта с заранее проверенной привязкой Router выбирает сайт автоматически и выполняет вход в своём окне. Предварительный вход в штатном Check Point не является обязательным действием каждого пользователя. Остальные профили Check Point сохраняются. Если официальный сеанс уже активен, его передача Router требует согласия.

Неизвестная или изменившаяся привязка требует отдельной проверки; произвольный сайт не получает доверие только по DNS или выбранной строке в интерфейсе. IP подключения может обновляться, но проверка личности шлюза и pin сохраняется. При отказе SSL с проверенным кодом 205 поддержанный профиль использует IPsec; порядок факторов задаёт шлюз.

Ниже — история 0.3.6–0.3.8 и отдельные инструменты диагностики SOTA. Они не заменяют текущую инструкцию входа и не доказывают причину конкретного сбоя. Не выполняйте восстановление на работающей сети. Для новых обращений сначала сохраните отчёт через «Диагностика…».

## Исторические сценарии


## Вход через другой сайт в 0.3.8

Для первого входа подключитесь к назначенному сайту в штатном Check Point. Когда появится Connected, нажмите «Подключить» в Router. При наличии DNS-имени сайта в сертификате Router проверяет его при каждом TLS-соединении. Внешний IPv4 может меняться между попытками.

Для другого сайта стартового комплекта с единственным внутренним IPv4 в сертификате Router сверяет имя активного шлюза в записи этого сайта с именем сертификата и проверяет отпечаток CA в штатном клиенте. После успешной проверки Router запоминает точный сертификат. При следующих подключениях проверяются цепочка, сохранённый сертификат и запись штатного клиента. Неоднозначный шлюз или замена сертификата останавливают вход. Если CA отличается от заранее подтверждённого, для первой привязки нужен его SHA-256 из независимого доверенного источника.

## Что изменилось в Router 0.3.7

Приватный комплект для Apple Silicon содержит новый системный помощник. Владелец Mac обновляет его один раз кнопкой «Обновить помощник маршрутов…» в главном окне. При первом использовании macOS предложит его установить. Пока помощник предыдущей версии обслуживает сеанс или завершает очистку, Router ждёт.

При входе Router определяет сайт Check Point, проверяет адреса DNS macOS и ждёт готовности корпоративного туннеля. После успешной авторизации и проверки локального SOCKS Router снова проверяет DNS. Только затем он создаёт рабочий интерфейс и публикует настройки DNS для рабочих доменов. Рабочие ссылки можно открывать, когда в окне появится «Подключено».

Если DNS-сервер действующего подключения использует адрес из диапазона Router, подключение останавливается. Проверка охватывает IPv4, IPv6 и DNS отдельных сетевых интерфейсов. Во время работы проверка повторяется перед добавлением адресных маршрутов и периодически во время проверки связи с помощником.

При отключении помощник завершает свой адаптер и сверяет оставшиеся сетевые настройки со своим журналом. Когда macOS повторно выдаёт имя интерфейса другому VPN, помощник сохраняет его маршруты. Если завершение остаётся неопределённым, помощник сохраняет журнал для повторной проверки, а Router блокирует новый вход.

Эти меры проверены на изолированных сценариях. Чтобы установить причину уже случившегося сбоя на конкретном Mac, нужен отчёт с включённой SOTA в момент потери доступа. Для этого подходит отдельный комплект SOTA Recovery.

С версии 0.3.6 Router обрабатывает каждый блок подписанного штатного клиента отдельно: имя, IPv4 и состояние должны относиться к одному сайту. На новой установке с несколькими сайтами подключитесь в Check Point к назначенному сайту и оставьте его подключённым до запроса Router на передачу соединения. Выделение строки в настройках не доказывает, что это действующий сайт. После первой подтверждённой привязки Router использует сохранённый сайт и при отключённом Check Point. Если активен другой сайт или изменилась привязка, Router останавливается.

Исходный преднастроенный сайт по-прежнему требует полного совпадения имени, IPv4, CN и SHA-256 CA. Другой сайт впервые привязывается только при подтверждённом штатном соединении с ним, совпадении DNS, IP SAN, действительного TLS и однозначного pin из Check Point. При той же CA пользователь подтверждает отдельную привязку. Для другой CA требуется SHA-256 от ИТ, полученный независимо: Router не предлагает скопировать значение из полученной цепочки. Router повторно проверяет активное соединение после подтверждения. Имена, отпечатки, пароли и OTP не попадают в журнал событий. Изменение уже сохранённой привязки этим сценарием не поддерживается.

## Если с SOTA пропадает интернет

Для уже выключенного Router используйте отдельный комплект SOTA-Recovery. Распакуйте ZIP при работающем интернете, затем откройте «SOTA Recovery.command» в момент сбоя с включённой SOTA. Первичный снимок сохраняется до любых изменений.

При наличии отдельного процесса адаптера от root, ожидаемого адреса интерфейса и отсутствии процесса приложения инструмент проверяет хеш установленного помощника версии 0.3.5, параметры его задания launchd и идентификатор владельца. После согласия он повторно проверяет эти признаки и просит штатный помощник завершить сессию по своему журналу.

Для исправления DNS нужны два положительных ответа от настроенного резолвера по IPv4-записям, успешный TCP хотя бы к одному публичному адресу и ошибки системного разрешения имён для обоих сайтов. Тогда инструмент предложит обновить кэш системной службы DNS. После каждого выполненного действия пробы повторяются. Результаты показываются на экране и сохраняются в один Router-SOTA-*.txt на рабочем столе или в Загрузках.

## Как читать результат

Сопоставьте результаты по IP, DNS и HTTPS, полученные в момент сбоя. Если с SOTA TCP к обоим публичным IP проходит, а системное разрешение обоих имён и HTTPS по имени перестают работать — сначала исследуйте DNS. Если перестают проходить и TCP по IP, и HTTPS, проверьте состояние туннеля SOTA и выбранные маршруты: это шире, чем простая ошибка разрешения имени. Если прямой HTTPS проходит, а приложения не работают, проверьте, меняется ли системный прокси/PAC или фильтр приложений. Эти проверки не диагностируют все причины и не измеряют IPv6-доступность.

Номер utun сам по себе не доказывает владение. Сверяйте адрес интерфейса, процесс адаптера Router, его помеченные resolver-файлы и адресные маршруты. Наличие службы Router на диске не означает активную сессию. Разбор статуса «несколько сайтов» в 0.3.5 предшествовал запуску маршрутизации этой попытки. О предыдущих попытках и состоянии другого VPN он ничего не говорит.
