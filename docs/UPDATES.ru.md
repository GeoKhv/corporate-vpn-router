# Встроенные обновления

Sparkle 2.10.1, macOS 13+, arm64. Пользователь видит обычную версию из трёх чисел. CFBundleVersion — возрастающий внутренний номер (3000, 3001, 3002, 3003).

Постоянная лента: https://github.com/GeoKhv/corporate-vpn-router/releases/download/update-channel/appcast.xml
Пакеты: GitHub Releases, отдельный тег v0.3.x. Клиент не содержит GitHub-токенов. GitHub Actions не используются.

При запуске и затем раз в сутки Sparkle проверяет ленту. Начиная с 0.3.3 запуск вызывает проверку явно, даже если прошлый запуск проверял недавно. Пункт меню «Проверять обновления автоматически» отключает проверки; ручная кнопка остаётся доступна. Обнаружение меняет отметку в прежнем окне/меню. Загрузка и установка требуют явного «Загрузить и установить» с предупреждением о завершении рабочего сеанса. Во время загрузки доступна отмена в меню Router. Автоматическая загрузка и установка запрещены Info.plist; системная статистика не отправляется.

После проверки Ed25519-подписи Sparkle подготавливает пакет. Router сохраняет точную копию текущего .app, завершает собственный сеанс, ждёт окончания engine/controller и независимо проверяет у root-помощника active=false и cleanupPending=false. Если копия или очистка не подтверждены, установка отменяется. Только затем Sparkle заменяет приложение и запускает его снова. Новый сеанс требует нового входа: пароли, OTP и MFA не воспроизводятся. Личный VPN не останавливается.

## Приватная настройка и общий пакет

Стартовый архив передаётся приватно. При запуске он переносит утверждённый профиль шлюза, сертификатные материалы, начальную таблицу адресов и ограниченный помощник в `~/Library/Application Support/Corporate VPN Router/Provisioning` без замены существующих данных. Сертификаты этим действием не импортируются и доверие Keychain не меняется.

Рабочие правила, сохранённая привязка шлюза, логины, настройки сертификатов и постоянная таблица синтетических адресов уже лежат в Application Support. Обновление не сбрасывает их. Обычные UserDefaults остаются привязаны к прежнему bundle ID.

Публичный пакет не содержит корпоративных доменов, адресов, CA, профиля или daemon с зашитой корпоративной политикой. Начиная с 0.3.3 также исключены обе неиспользуемые копии sing-box: действующий адаптер находится в системной установке помощника, точный приватный резерв — в Provisioning. Остаются проверенный RouteClient, runtime и код приложения.

Daemon, его ограниченный набор операций, политика и точный cdhash RouteClient сохраняются. Протокол остаётся совместимым с установленным помощником. Приложение не устанавливает root-компоненты через Sparkle. Повторная явная установка/восстановление помощника возможна только из приватной копии, проверенной по SHA-256, с объяснённым запросом администратора. Изменение помощника требует отдельного релизного решения; нельзя просто пересобрать RouteClient, добавить произвольные root-команды или ослабить проверку вызывающего кода.

Sparkle заменяет запущенный bundle по его исходному пути. Существующий установщик также уважает `/Applications` и `~/Applications`. Bundle ID и имя папки сохранены для совместимости. Общий ZIP — обновление ранее подготовленной установки, не стартовый пакет для коллег.

## Подписи и системные запросы

Пакет и сама лента подписываются Ed25519. `SUVerifyUpdateBeforeExtraction=true`, `SURequireSignedFeed=true`, срок ослабления проверки ленты равен нулю. Публичный ключ находится в `packaging/updates/public-key.txt`. Закрытый ключ хранится только в login Keychain машины выпуска, account `com.geokhv.corporate-vpn-router.updates`, service `https://sparkle-project.org`.

Code signing приложения остаётся ad hoc: Developer ID и notarization нет. Интеграция не отключает Gatekeeper, SIP, проверку сертификатов или библиотек, не добавляет разрешающих entitlements и не удаляет quarantine. На первом запуске macOS может требовать штатного разрешения для неподписанного Developer ID приложения. Sparkle не заменяет это доверие своей подписью. Для защищённого `/Applications` системный запрос администратора зависит от прав папки/владельца. В пользовательской папке проверенный переход не требовал новой установки route helper.

## Выпуск следующей версии вручную

1. Получить официальный Sparkle 2.10.1 и сверить архив SHA-256 `1a856d2a9edb8e628de88121d7be04cf0e2167f8641650b78fca00b14244cf27`. Не пересобирать его helper без необходимости. Сохранить symbols.
2. На машине выпуска взять проверенный базовый .app, текущие исходники и существующий Keychain. Новую пару ключей для обычного выпуска не создавать.
3. Собрать: `python3 scripts/build-update.py --base-app /path/Base.app --sparkle /path/Sparkle --output /private/tmp/release-0.3.4 --version 0.3.4 --build 3004`. Для приватной стартовой сборки добавить `--private` и использовать приватную базу. Сборка никогда не перезаписывает существующий результат.
4. Запустить `scripts/audit-update.py APP --private-reference PRIVATE_BASE_APP`; вручную проверить состав и новые зависимости. Публичный код также проверить отдельно. При изменении данных политики/помощника не публиковать пакет как совместимое обычное обновление.
5. Упаковать только .app командой `ditto -c -k --sequesterRsrc --keepParent APP releases/Corporate-VPN-Router-0.3.4-arm64.zip`. Приватные и общие ZIP хранить в разных папках.
6. `generate_appcast --account com.geokhv.corporate-vpn-router.updates --maximum-deltas 0 --download-url-prefix https://github.com/GeoKhv/corporate-vpn-router/releases/download/v0.3.4/ releases`. Для существующей общей ленты сохранять URL предыдущих enclosure. Не редактировать XML после подписания без повторной подписи.
7. Сначала опубликовать проверенный ZIP в отдельном релизе, проверить публичную загрузку и SHA-256, затем заменить только `appcast.xml` в релизе `update-channel`. После сетевой ошибки проверить существование релиза/asset, не повторять вслепую.
8. Проверить переход с предыдущей реальной версии, кодовую подпись, исходный путь, настройки, очистку и новый MFA. Сохранить SHA пакета, коммит, протокол и результат тестов. Не использовать только успешное скачивание как критерий.

## Защищённая резервная копия ключа

В обычном интерактивном Terminal выполнить `scripts/update-key-backup.sh export /path/offline/cvr-signing-key.encrypted.json`. Ввести отдельную длинную парольную фразу. Утилита читает ключ непосредственно из Keychain, шифрует AES-256-GCM с PBKDF2-HMAC-SHA256 (600000 итераций, случайная соль), проверяет расшифрование в памяти и пишет только шифротекст с правами 0600. Ключ и пароль не попадают в argv, stdout или незашифрованный файл. Хранить копию офлайн, пароль отдельно. `--self-test` проверяет круговой проход, неверный пароль и подмену метаданных на случайном тестовом ключе.

Восстановление на машине выпуска: `scripts/update-key-backup.sh restore /path/cvr-signing-key.encrypted.json`. Отличающийся существующий ключ не заменяется. Сверить публичный ключ с репозиторием. Создание реальной офлайн-копии требует участия владельца и выбранного им пароля/носителя; автоматический тест не является резервной копией производственного ключа. При потере ключа ad-hoc-сборка с обязательной Ed25519-проверкой потребует ручного доверенного распространения новой стартовой версии.

## Откат

Перед каждым обновлением Router сохраняет .app в `~/Library/Application Support/Corporate VPN Router/UpdateBackups/<version>-<UUID>/` вместе с `restore.json` (исходный путь). Sparkle выполняет атомарную замену, а при недоступности swap — перемещение с попыткой восстановить старую app при ошибке финального rename.

Для ручного отката: штатно отключить рабочий сеанс, дождаться удаления маршрутов, закрыть Router и восстановить точную app из выбранной копии в путь `originalPath`. Не копировать поверх работающего приложения. Не заменять Application Support, root-helper, личный VPN или Keychain. После запуска выполнить новый вход. Временно отключить автопроверку, если требуется остаться на прежней версии. Sparkle не выполняет downgrade из ленты; плохой выпуск убирается из подписанной ленты, исправление публикуется с большим номером.
