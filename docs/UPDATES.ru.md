# Обновления и откат

С версии **0.3.27 by MichaelTG** у RED и WHITE один номер выпуска и разные подписанные ленты. Все установки до разделения используют ленту RED. В WHITE готовый рабочий профиль отсутствует. [Скачать сборки](../README.md) · [Лента RED](https://github.com/GeoKhv/corporate-vpn-router/releases/download/update-channel/appcast.xml) · [Лента WHITE](https://github.com/GeoKhv/corporate-vpn-router/releases/download/update-channel-white/appcast.xml)

## Как обновляется приложение

В окне Router нажмите **«Проверить обновления»**. Автоматическую проверку можно включить или выключить в меню «Обновления». Загрузка и установка требуют подтверждения **«Загрузить и установить»**. Во время загрузки доступна отмена в меню. В 0.3.28 кнопка «Проверить снова» закрывает найденное предложение и читает ленту заново. «Отмена» закрывает предложение и возвращает кнопку проверки.

Sparkle проверяет подписи пакета и ленты Ed25519. Router сохраняет резервную копию, завершает рабочий сеанс и проверяет очистку маршрутов у помощника. После подтверждения очистки Sparkle заменяет приложение по исходному пути и запускает его заново. Для нового подключения потребуется MFA. Личный VPN продолжает работать.

Рабочий список, привязка шлюза, настройки, сертификатные материалы и таблица адресов хранятся отдельно в `~/Library/Application Support/Corporate VPN Router`. Установка поверх Router сохраняет эти данные. RED загружает стартовый профиль при отсутствии рабочего списка. На существующем профиле RED добавляет новые адреса при подключении. Уже применённые правила можно изменить или удалить вручную. При утверждении новых разрешений macOS может показать отдельный запрос администратора.

### Если старая версия пишет «очистка или копия не подтверждена»

Эта надпись в 0.3.28 и 0.3.29 объединяет несколько ошибок. Если в приложении появились файлы кэша Python, проверка подписи перед резервным копированием остановит обновление. Для восстановления можно отключить рабочие маршруты, закрыть Router и повторить установку из опубликованного ZIP своей редакции. Список рабочих сайтов хранится отдельно. С версии 0.3.30 проверка адреса запускает Python с отключённой записью кэша, а при ошибке подготовки обновления появляется окно с причиной.

## Запуск службы Check Point при подключении

Если при нажатии «Подключить» Check Point сообщает, что служба остановлена, Router проверяет её регистрацию в macOS. Обновлённый помощник может загрузить отсутствующую штатную службу. Разрешение на это действие macOS запрашивает при установке помощника. Затем Router дожидается ответа Check Point и продолжает тот же вход. Если служба отключена администратором или её установку не удалось проверить, причина появится в окне Router.

## Откат

1. Отключите рабочие маршруты и завершите Router.
2. Найдите предыдущую копию в `~/Library/Application Support/Corporate VPN Router/UpdateBackups/<version>-<UUID>/`. Файл `restore.json` содержит исходный путь. Для ручной установки используйте копию `.app`, которую сохранили перед заменой.
3. Верните прежний `.app` в исходную папку установки и откройте его оттуда. Данные в Application Support и настройки помощника сохраните. При необходимости используйте «Доступы… → Ещё → Вернуть предыдущие правила…» и подтвердите разрешения.

Sparkle предлагает только версии с большим номером сборки. Для выпуска исправления используйте новый номер.

## Подписи

Code signing приложения — ad hoc. Для первой установки macOS может запросить «Всё равно открыть». Ed25519 защищает доставку через Sparkle. Публичный ключ хранится в `packaging/updates/public-key.txt`, закрытый — в Keychain машины выпуска. Подпись автора в интерфейсе не участвует в сравнении версий. [Упаковка и проверка канала](BUILDING.ru.md)

## Защищённая резервная копия ключа

В обычном интерактивном Terminal выполнить `scripts/update-key-backup.sh export /path/offline/cvr-signing-key.encrypted.json`. Ввести отдельную длинную парольную фразу. Утилита читает ключ непосредственно из Keychain, шифрует AES-256-GCM с PBKDF2-HMAC-SHA256 (600000 итераций, случайная соль), проверяет расшифрование в памяти и пишет только шифротекст с правами 0600. Ключ и пароль не попадают в argv, stdout или незашифрованный файл. Хранить копию офлайн, пароль отдельно. `--self-test` проверяет круговой проход, неверный пароль и подмену метаданных на случайном тестовом ключе.

Восстановление на машине выпуска: `scripts/update-key-backup.sh restore /path/cvr-signing-key.encrypted.json`. Отличающийся существующий ключ не заменяется. Сверить публичный ключ с репозиторием. Создание реальной офлайн-копии требует участия владельца и выбранного им пароля/носителя; автоматический тест не является резервной копией производственного ключа. При потере ключа ad-hoc-сборка с обязательной Ed25519-проверкой потребует ручного доверенного распространения новой стартовой версии.

### Локальная сборка с автовосстановлением DNS

Обновите помощник маршрутов после завершения рабочего соединения. В системном запросе macOS перечислены рабочие маршруты и разрешение на обновление DNS. В окне «Диагностика» можно включить или выключить «Восстанавливать DNS автоматически при подтверждённом сбое». При включённой настройке Router сравнивает адреса OWA и Jira после подключения. Помощник может обновить системный DNS только для действующего сеанса и зарегистрированного рабочего имени. Затем Router проверяет сайты повторно. При сбое HTTPS или отсутствии ответа от DNS Router системный кэш сохраняется.
