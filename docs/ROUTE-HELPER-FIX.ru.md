# Сохранённое исправление помощника маршрутов

Статус: исходники и регрессионные тесты подготовлены; общий выпуск с обновлением
установленных помощников ещё не выполнен. Локальная успешная проверка одного Mac
не означает, что исправление доставлено остальным пользователям.

## Исправлено

- После тайм-аута или превышения лимита вывода дочерний процесс не только
  получает SIGKILL, но и собирается через waitpid. Медленное завершение
  обрабатывается таймером без блокирования очистки маршрутов.
- Перед очисткой сохраняются стадия запуска, длительность проверки процесса,
  состояние дочернего процесса и фактический результат waitpid. ECHILD не
  записывается как успешный exit(0).
- Последняя ошибка и ограниченная копия журнала адаптера сохраняются отдельно
  от следующей попытки. Журнал остаётся доступным только root; через XPC status
  и сборщик диагностики передаются только поля фиксированной схемы.

Проверка из чистого checkout на macOS arm64:

```sh
bash scripts/test-route-helper.sh
```

Тесты используют синтетическую политику без корпоративных данных. Проверяются
реальные exit(7), SIGSTOP, SIGTERM, тайм-аут команды, лимит вывода и отсутствие
несобранных дочерних процессов. Работающий VPN и установленный помощник не
меняются.

## Обязательный пункт следующего выпуска

Обычный пакет Sparkle исключает RouteHelper и sing-box, а также сохраняет
существующий Provisioning. Он не доставит это исправление системной службе.
Копирование старого помощника из базового ZIP также не включает новые исходники.

Для выпуска этого исправления необходимо:

1. Собрать daemon именно из исправленных исходников, сохранив утверждённую
   политику, проверку точного RouteClient и ограниченный протокол. Приватную
   политику и соответствующий бинарный файл не включать в публичный пакет.
2. Ввести отдельный идентификатор сборки помощника. Совпадение старого номера
   протокола само по себе не доказывает наличие исправления.
3. Подготовить проверяемый способ обновления уже установленных помощников:
   отдельный приватный комплект либо предусмотренную приложением миграцию
   с явным подтверждением администратора. Нажатие «Подключить» не должно
   незаметно запускать установку.
4. Проверить старую установку: остановка Router, подтверждённая очистка,
   обновление помощника, новый вход, отсутствие zombie-процессов. Сверить
   настройки и сохранность другого VPN. Проверить повторный запуск приложения
   и целевой откат помощника.
5. Зафиксировать исходный коммит, идентификатор и SHA-256 нового помощника,
   состав пакета и результаты проверки. Только после этого объявлять
   исправление доступным остальным пользователям.

Это исправление устраняет доказанный дефект завершения дочерних процессов
и потерю диагностики. Первопричина исходного отказа запуска адаптера и её связь
с аварией loginwindow не установлены; гарантия устранения всех таких отказов
в описание выпуска не входит.
