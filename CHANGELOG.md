# История изменений

## 0.3.43 by MichaelTG · build 3043

В RED доступ к ПУРМС настраивается при подключении. Router использует готовый адрес и сохраняет ранее настроенный рабочий ПК. При первом подключении или обновлении разрешений достаточно подтвердить запрос macOS. Ввод имени ПК остаётся доступен при ручном редактировании. VDI через VMware Horizon открывается по обычному маршруту macOS.

## 0.3.42 by MichaelTG · build 3042

Исправлена кнопка проверки обновлений после фонового опроса Sparkle. В WHITE можно сохранить первый рабочий адрес при остановленной службе Check Point. Router проверяет DNS выбранного сайта и повторно сверяет выбор после временной ошибки DNS. При обновлении помощника сохраняются утверждённые TCP-правила и имя Windows-ПК. Установщик предлагает переход между RED и WHITE с одинаковым номером сборки. В RED VMware Horizon использует обычный маршрут macOS, если в профиле оставалось стандартное правило. Изменённое вручную правило сохраняется.

## 0.3.41 by MichaelTG · build 3041

В RED добавлена поддержка HTTP-ссылок на Superset и «Метрику». При следующем подключении Router предложит добавить TCP 80 к существующим точным HTTPS-правилам этих сайтов. Если macOS запросит подтверждение, проверьте список и подтвердите изменение.

## 0.3.40 by MichaelTG · build 3040

Когда Check Point уже подключён, Router показывает кнопку «Далее» и объясняет, что произойдёт с рабочим доступом. После нажатия Router сам переключает VPN. Вход продолжается в этом окне или в браузере, в зависимости от выбранного способа. Кнопка «Остаться в Check Point» сохраняет текущий сеанс.

## 0.3.39 by MichaelTG · build 3039

Исправлен выбор сайта Check Point, когда в списке есть отключённый профиль с IPv4-адресом в названии и другой, выбранный профиль с DNS-именем. Router проверяет сайт при подключении и повторно после перехода из штатного VPN. При ошибке для разбора достаточно обычного файла журнала целиком.

## 0.3.37 by MichaelTG · build 3037

При первом входе рабочие правила можно подготовить с уже установленным помощником. Перед включением маршрутов Router сверяет действующий сайт. Поддерживаются записи шлюза с явным портом 443 и DNS-именем с IPv4 в скобках при совпадении с DNS.

В обычном отчёте сохраняются причина отказа при чтении профиля, номер записи, типы полей, состояние клиента и время. Добавлены сведения о применении правил, способе входа и этапах резервного копирования и очистки при обновлении. Имена сайтов, адреса шлюзов и данные входа в эти поля не записываются.

## 0.3.36 by MichaelTG · build 3036

Помощник на новом Mac можно установить до входа в Check Point. Router сверяет выбранный шлюз перед включением маршрутов. Профили с подписью или IP в названии распознаются, когда адрес однозначно соответствует известному сайту. Поддерживается DNS-имя в поле шлюза.

Обновление при первой установке учитывает подтверждённое отсутствие службы и её файлов. На предыдущих версиях при ошибке подготовки можно открыть новую сборку из ZIP после завершения Router. Исправлена загрузка модулей диагностики и предупреждение встроенного Python. Снимок при активном штатном VPN сохраняется без переключения подключения.

## 0.3.35 by MichaelTG · build 3035

Router восстанавливает сохранённые IPv4- и IPv6-маршруты парами и ждёт их готовности перед запуском локального DNS. Медленное восстановление маршрутов больше не прерывает подключение через 15 секунд.

## 0.3.34 by MichaelTG · build 3034 · RED

## 0.3.31 by MichaelTG · build 3031

## 0.3.30 by MichaelTG · build 3030

## 0.3.19 · build 3019 · 17 ноября 2026

- Общий запрос `password:` получает подпись соответствующего фактора выбранного шлюза. Конкретные динамические запросы сохраняются; отсутствующие подписи не сдвигают порядок факторов. Ответы MFA не сохраняются и не воспроизводятся.
- Диагностика HTTPS показывает проверяемый адрес и отдельную причину ошибки. Ограниченный GET заменяет HEAD. HTTP-ответ, включая отказ в доступе, подтверждает транспорт и TLS, но не права пользователя внутри сайта.
- Числовые результаты curl, HTTP и TLS включаются в отфильтрованный отчёт. Ошибка одного адреса не объявляется отказом всех рабочих сайтов.
- После успешного сохранения TXT-файл копируется в буфер для вставки Cmd+V и открывается. Отмена и ошибка записи не заменяют содержимое буфера.
- Исправлено копирование текстов лицензий при упаковке с файловой системы macOS с дополнительными атрибутами.

## 0.3.18 · build 3018

Удалён неиспользуемый запрос CCC ClientSettings после IPsec-авторизации, который шлюз отклонял. Адрес, DNS и параметры ESP берутся из аутентифицированного IKE. Правила доступа SOCKS и проверки сертификата остаются обязательными. Пользователь подтвердил на компьютере получателя вход по OTP и паролю и работу рабочих и внешних сайтов с внешним VPN.

## 0.3.17 · build 3017

Добавлен отдельный непривилегированный модуль IKEv1/IPsec через TCPT для проверенного отказа SSL Network Extender с кодом 205. До ввода секретов проверяются сертификат и подпись IKE. Модуль передаёт пакеты существующему ограниченному SOCKS и сам не изменяет системные маршруты. Браузерный вход в этом транспорте не реализован. В этом выпуске последующий запрос CCC ещё мешал завершению подключения; исправление — 0.3.18.

## 0.3.14–0.3.16

Добавлены поставляемая проверенная привязка альтернативного сайта и автоматический выбор поддержанного сайта при нескольких записях Check Point. Расширена отфильтрованная диагностика этапов и причин завершения SSL. Исправлен экспорт отчёта из изолированного Python приложения.
